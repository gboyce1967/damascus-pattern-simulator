# Damascus Pattern Simulator - Development Notes

**DO NOT COMMIT THIS FILE TO GIT** - For AI assistant reference only

## Project Overview
Damascus steel pattern simulator for bladesmiths. Simulates layered steel patterns with transformations (twist, grind, mosaic). Built with Python/Tkinter for Linux.

## Current Version: 2.3.0-beta (March 2026)

## Dual Interface Architecture

The simulator now has **two frontends**:

### 1. Legacy Tkinter GUI (`damascus_3d_gui.py`)
- Original desktop GUI, uses VisPy for 3D viewport
- Full feature set with all dialogs
- Entry point: `python damascus_3d_gui.py`

### 2. Electron + React UI (NEW — March 2026)
- Modern web-based UI built with Electron, React, Tailwind CSS
- FastAPI Python backend spawned by Electron
- Three.js WebGL 3D viewport
- Entry point: `npm run dev` (development) or packaged Electron app
- Key files:
  - `src/main/` — Electron main process, spawns Python backend
  - `src/renderer/src/` — React components (App, Sidebar, Viewport3D, CrossSection, Timeline)
  - `src/preload/` — Electron preload bridge
  - `python/engine/` — FastAPI backend (`server.py`, `session.py`, `forge_ops.py`, `serialize.py`)
  - `python/vendor/` — Symlink shim importing from `lib/`

### Coordinate System (3D Viewport)
- **Engine coordinates**: X=width, Y=length, Z=height (layers stack in Z)
- **Three.js scene**: X=width, Y=height(up), Z=length
- Axis remap done at vertex level in `Viewport3D.tsx` when loading mesh data
- Billet origin is at (0,0,0) — bottom corner sitting on the build plate
- Build plate (grid) is the fixed reference frame; billet is placed on it
- Grid auto-resizes only when billet dimensions exceed it

## Key Architecture Decisions

### Pattern Representation (Legacy 2D)
- Patterns stored as numpy arrays (height, width, 3) - RGB format
- `self.pattern_array` = base pattern (before transformations)
- Transformations applied in order: rotation → mosaic → twist → grind
- Display uses PIL/ImageTk for canvas rendering

### Transformation Order (CRITICAL)
1. Rotation (90° increments)
2. Mosaic (tiling)
3. Twist (radial spiral)
4. Grind (cross-section slice)

**DO NOT change this order** - breaks save_pattern_as_layer() functionality

### Twist Algorithm (Version 1.3)
- **End-grain view**: Looking at the END of a twisted round bar
- Uses **radial/polar coordinates** from center point
- Formula: `twist_angle = radius * twist_rate`
- Rotates sampling angle based on distance from center
- More twist at edges, less at center (physically accurate)

### Grind Algorithm
- Simulates grinding from the SIDE (perpendicular to end grain)
- Samples vertical slices at different depths
- X-axis = depth into material
- Grind angle creates beveled surface (0-45°)

### Custom Layer Builder
- Stores layer stack in `self.layers` list of dicts
- Each layer: `{'color': 'white'|'black'|'pattern', 'thickness': float}`
- Pattern layers include: `'pattern_image': numpy_array, 'pattern_name': str`
- **IMPORTANT**: When editing layers, preserve pattern_image/pattern_name fields
- Uses `self.last_custom_layer_stack` to reopen with previous state

### Canvas Background System
- `self.canvas_bg_image` = PIL Image for tiled background
- Canvas items tagged: "bg" for background, "pattern" for pattern
- `update_pattern()` only deletes "pattern" tag to preserve background
- Default: Gray Works Crafts logo tiled on hot green background

### Display Scaling Logic
- Wide patterns (aspect > 4:1): height-based scaling up to 20x
- Normal patterns: fit-to-canvas scaling (max 1.0x, no upscaling)
- Target display height: 600px for wide patterns
- Handles pattern layers that scale height only (preserve horizontal detail)

## Critical Variables

### Instance Variables
```python
self.pattern_array         # Base pattern (numpy array)
self.display_image         # PhotoImage for canvas
self.canvas_bg_image       # Background image (PIL)
self.twist_amount          # DoubleVar (0-10)
self.grind_depth           # DoubleVar (0-100%)
self.grind_angle           # DoubleVar (0-45°)
self.rotation_angle        # IntVar (0/90/180/270)
self.mosaic_size           # IntVar (1-3 for quick mosaic)
self.custom_layer_stack    # Current custom layers
self.last_custom_layer_stack  # For reopening builder
```

### Units & Scaling
- Layer thickness: mm (converted via `self.pixels_per_mm = 10`)
- Pattern dimensions: pixels
- Export: 300 DPI
- Display: fit-to-canvas with special wide pattern handling

## Known Issues & Gotchas

1. **Twist on horizontal stripes**: Should work now (v1.3) - radial algorithm rotates any pattern
2. **Pattern array must exist**: `update_pattern()` returns early if None
3. **Canvas background persistence**: Must tag items correctly ("bg" vs "pattern")
4. **Layer edit dialog**: Must preserve pattern_image/pattern_name when saving
5. **GTK print**: Requires python3-gi and gir1.2-gtk-3.0
6. **PEP 668**: Use system packages (python3-pil, python3-numpy) not pip on modern Ubuntu

## Electron UI Components

### Sidebar (`Sidebar.tsx`)
- Collapsible `<Section>` components with ▶ toggle
- Feather (Wedge Split) — collapsed by default
- Forge to Square Bar — bar size + heats
- Forge to Octagonal Bar — bar size + heats + chamfer %
- Twist — slider in full twist count (0–30), sends `count * 360` degrees
- Export — OBJ/STL/PLY

### Viewport3D (`Viewport3D.tsx`)
- Three.js scene with OrbitControls
- Vertex-level axis remap (engine Y→scene Z, engine Z→scene Y)
- ResizeObserver for flex-based container resizing
- Build plate grid auto-scales to billet footprint

### Backend (`python/engine/`)
- `forge_ops.py` — Headless wrappers: `apply_wedge_safe`, `apply_twist_safe`,
  `apply_compression_safe`, `drill_hole_safe`, `forge_to_square_safe`,
  `forge_to_octagon_safe`, `cross_section_png_safe`
- `session.py` — `SessionManager` + `EngineSession` managing billet lifecycle
- `serialize.py` — Converts Open3D meshes to JSON-friendly vertex/triangle arrays
- `server.py` — FastAPI endpoints for all operations

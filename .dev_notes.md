# Damascus Pattern Simulator - Development Notes

**DO NOT COMMIT THIS FILE TO GIT** - For AI assistant reference only

## Project Overview
Damascus steel pattern simulator for bladesmiths. Simulates layered steel patterns with transformations (twist, grind, mosaic). Built with Python/Tkinter for Linux.

## Current Version: 2.3.0-beta (March 2026)

## Dual Interface Architecture

The simulator now has **two frontends**:

### 1. Legacy Tkinter GUI (`damascus_3d_gui.py`)
- Original desktop GUI, uses VisPy for 3D viewport
- Full feature set with all dialogs
- Entry point: `python damascus_3d_gui.py`

### 2. Electron + React UI (NEW — March 2026)
- Modern web-based UI built with Electron, React, Tailwind CSS
- FastAPI Python backend spawned by Electron
- Three.js WebGL 3D viewport
- Entry point: `npm run dev` (development) or packaged Electron app
- Key files:
  - `src/main/` — Electron main process, spawns Python backend
  - `src/renderer/src/` — React components (App, Sidebar, Viewport3D, CrossSection, Timeline)
  - `src/preload/` — Electron preload bridge
  - `python/engine/` — FastAPI backend (`server.py`, `session.py`, `forge_ops.py`, `serialize.py`)
  - `python/vendor/` — Symlink shim importing from `lib/`

### Coordinate System (3D Viewport)
- **Engine coordinates**: X=width, Y=length, Z=height (layers stack in Z)
- **Three.js scene**: X=width, Y=height(up), Z=length
- Axis remap done at vertex level in `Viewport3D.tsx` when loading mesh data
- Billet origin is at (0,0,0) — bottom corner sitting on the build plate
- Build plate (grid) is the fixed reference frame; billet is placed on it
- Grid auto-resizes only when billet dimensions exceed it

## Key Architecture Decisions

### Pattern Representation (Legacy 2D)
- Patterns stored as numpy arrays (height, width, 3) - RGB format
- `self.pattern_array` = base pattern (before transformations)
- Transformations applied in order: rotation → mosaic → twist → grind
- Display uses PIL/ImageTk for canvas rendering

### Transformation Order (CRITICAL)
1. Rotation (90° increments)
2. Mosaic (tiling)
3. Twist (radial spiral)
4. Grind (cross-section slice)

**DO NOT change this order** - breaks save_pattern_as_layer() functionality

### Twist Algorithm (Version 1.3)
- **End-grain view**: Looking at the END of a twisted round bar
- Uses **radial/polar coordinates** from center point
- Formula: `twist_angle = radius * twist_rate`
- Rotates sampling angle based on distance from center
- More twist at edges, less at center (physically accurate)

### Grind Algorithm
- Simulates grinding from the SIDE (perpendicular to end grain)
- Samples vertical slices at different depths
- X-axis = depth into material
- Grind angle creates beveled surface (0-45°)

### Custom Layer Builder
- Stores layer stack in `self.layers` list of dicts
- Each layer: `{'color': 'white'|'black'|'pattern', 'thickness': float}`
- Pattern layers include: `'pattern_image': numpy_array, 'pattern_name': str`
- **IMPORTANT**: When editing layers, preserve pattern_image/pattern_name fields
- Uses `self.last_custom_layer_stack` to reopen with previous state

### Canvas Background System
- `self.canvas_bg_image` = PIL Image for tiled background
- Canvas items tagged: "bg" for background, "pattern" for pattern
- `update_pattern()` only deletes "pattern" tag to preserve background
- Default: Gray Works Crafts logo tiled on hot green background

### Display Scaling Logic
- Wide patterns (aspect > 4:1): height-based scaling up to 20x
- Normal patterns: fit-to-canvas scaling (max 1.0x, no upscaling)
- Target display height: 600px for wide patterns
- Handles pattern layers that scale height only (preserve horizontal detail)

## Geometry Overhaul (May 2026)
Every forging operation had the same class of bugs: too few vertices, wrong
coordinate assumptions, hardcoded billet dimensions instead of actual geometry.
All operations were rewritten to use a shared utility layer.

### New shared module: `lib/forging_utils.py`
- `BilletFrame` — lightweight container with min/max/center/span for X, Y, Z
- `compute_billet_frame(billet)` — builds a BilletFrame from ALL current vertex
  positions.  Shape-agnostic (works after square, octagon, wedge, twist, etc.).
- `subdivide_if_needed(billet, ...)` — Open3D midpoint subdivision, skips layers
  already ≥200 verts.  Extra iterations scale with deformation magnitude.

### Per-module fixes

**lib/forging_twist.py**
- Mesh subdivision before twisting (8 → ~386 verts/layer).
- Rotation center from actual geometry centroid, not X=0 / per-layer Z.
- Y normalization from actual y_min/y_max, not `billet.length`.
- Vectorized numpy rotation (no per-vertex Python loop).

**lib/forging_wedge.py**
- `center_x` now comes from `compute_billet_frame`, not hardcoded 0.
- Height-based intensity uses actual vertex Z positions, not `layer.z_position` metadata.
- Gaussian sigma uses actual X span, not `billet.width`.
- Subdivided + vectorized.

**lib/forging_drill.py**
- Distance now computed in X-Z plane (was using X-Y — the LENGTH axis).
- Displacement pushes radially in X-Z (was pushing along length).
- Subdivided + vectorized.

**lib/forging_compression.py**
- Vectorized (minor: replaced per-vertex loop with `vertices[:, 2] *= factor`).

**python/engine/forge_ops.py — forge_to_square_safe**
- Center-relative scaling (offset vertices to centroid, scale, translate back).
- Volume computed from actual vertex spans, not `billet.width * billet.length`.

**python/engine/forge_ops.py — forge_to_octagon_safe**
- Mesh subdivision before chamfering (so there are enough vertices for facets).
- Chamfer now operates on X-Z cross-section (was checking X-Y = length axis).
- Octagon area formula corrected: 0.8284·s² (was 0.95·s²).
- Center-relative scaling.
- Diagonal threshold `|x|/half_w + |z|/half_h` clips corners properly.

### Physics basis
Per `Research/material-deformation-math.md`:
- Vertex displacement approach (move mesh vertices by deformation map)
- Gaussian falloff for wedge and drill influence zones
- Laminate theory: each layer tracked separately, centroid from composite bounds
- All operations shape-agnostic — forge to octagon then twist works correctly

## Twist Guidelines UI/Metadata (May 25, 2026)
Twist controls now include a numeric twists input in addition to the slider.
The UI calculates recommended total twist ranges from the current billet length:

- Standard Damascus: 3–4 twists per inch
- Turkish twist: 5–10 twists per inch

The slider max grows to cover the Turkish upper guideline for the current billet
length, while the number input allows up to 1000 full rotations for edge cases.
`lib/forging_twist.py` records twist metadata in operation history:

- `total_twists`
- `billet_length_inches`
- `twists_per_inch`
- `guideline_band`
- standard and Turkish reference ranges

## Twist Shortening/Rounding Fix (May 25, 2026)
Twist deformation now models hot-twist material flow instead of pure rotation.
The twist field now:

- Compresses billet length along the Y axis, with shortening scaled by
  twists-per-inch. Standard-density twisting is intentionally aggressive so a
  50-twist, 16.6 inch billet compresses from roughly 3 twists/in before twist
  to about 10 twists/in after twist.
- Derives cross-section rounding from that compression rather than applying a
  separate cosmetic roundness effect.
- Maps the X-Z cross-section toward an area-preserving round target as
  compression approaches standard/high twist densities, so long billets lose
  flats and read more like threaded round bar than a corkscrew.
- Records `axial_scale`, `axial_shortening`, `roundness_factor`, and
  `target_round_radius` in twist operation history.

The validation suite now runs the twist case at 10 full rotations and asserts
that twist strongly shortens length, grows height toward a round bar, and
finishes with a near-round X/Z aspect ratio.

## Fused Billet Material Field Rendering (May 25, 2026)
The Electron viewport now treats a twisted Damascus billet as a fused body with
an internal material field, instead of rendering every configured layer as a
separate physical slab. Twist records pre-twist material intervals and
deformation metadata. The backend then generates a continuous visible surface
and colors it by inverse-mapping surface samples back into the original
material/layer coordinates.

This preserves the purpose of the simulator: the visible pattern comes from the
steel layers that would be exposed on the current surface, while internal
forge-welded layer boundaries no longer appear as false screw-flight geometry.

Twist end caps are generated from a dense source X/Z grid rather than polar
triangle rings. Their material lookup takes the original flat layer field and
applies a smooth radius-dependent spiral warp, so the end-grain view reads as
twisted layer lines instead of checkerboard or mosaic sectors.

## Handoff: Through-Volume Material Field Pivot (May 25, 2026)
The simulator work paused after a major architectural clarification: the application must generate and preserve Damascus pattern information through the full billet volume, not just make the outside surface look correct.

### Current decision
- A forge-welded billet must be treated as one continuous steel body with an internal material-coordinate field.
- Viewport colors, end faces, cut faces, grind faces, cross-sections, and exports must all sample the same material field.
- Twist end patterns should be represented as cut planes through the twisted internal field after the smith trims the malformed ends, not as generated decorative caps.
- Future operations such as cut, stack, forge-weld, draw, twist left/right, grind square, and knife shaping need to preserve and compose material fields.

### Current code state to revisit
- `lib/forging_visible_surface.py` contains transitional fused render-surface work, including cap/end logic that should not be treated as final architecture.
- `lib/forging_twist.py` records useful twist metadata such as axial scale, shortening, roundness, source spans, centers, and material intervals.
- `python/engine/session.py` can return fused render geometry after Twist, but this is a compatibility/render path rather than a true through-volume material-field implementation.
- The active plan document was revised to “Through-Volume Material Field Architecture.” Continue from that plan rather than patching cap visuals.
